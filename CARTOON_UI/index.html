Cartoon UI — components, interaction and animation

An optional React-Lua skin extracted from Coin Hunt's existing UI. The source audit in CARTOON_UI_AUDIT.md records colors, dimensions, interactions, responsive behavior and the presentation/gameplay boundary.

Rojo maps the package output under ReplicatedStorage.rbxts_include.node_modules.@frameactive-studio. Cartoon UI contains no authoritative server code. Future modules with server implementations require side-specific mappings as documented in MODULES.md.

Register the manifest before the runtime starts:

import CartoonUIModule from "@frameactive-studio/cartoon-ui/module";
import { RoFrame } from "@frameactive-studio/core";

RoFrame.registerModule(CartoonUIModule);
RoFrame.configureModules({ modules: { "cartoon-ui": true } });
// Then call the game's existing startClient/startServer bootstrap.

The manifest defaults to disabled, declares no invented dependency on a UI module, imports no React and allocates no UI/Remotes/Stores. Server registration is optional and safe. Server/bootstrap code should import module.ts, not the client barrel. Core never imports Cartoon UI.

Core activation controls module lifecycle; components remain ordinary library code. The consuming game must gate its mount as well. Check RoFrame.isModuleEnabled("cartoon-ui") after awaiting runtime startup, or use the same game activation flag for registration and mounting. Core currently starts Controllers before module hooks, so this query inside a Controller's start() is too early. No Core lifecycle behavior was changed.

Theme and composition​

Create themes outside render functions and mount through the existing UIController. The provider uses the demo-derived theme when no theme is supplied.

import React from "@rbxts/react";
import { Screen } from "@frameactive-studio/core/ui";
import {
  CartoonThemeProvider, CartoonPanel, CartoonText, CartoonButton,
  createCartoonTheme,
} from "@frameactive-studio/cartoon-ui";

const gameTheme = createCartoonTheme({
  colors: { primary: Color3.fromRGB(134, 108, 245) },
  typography: { heading: { size: 34 } },
});

export function Inventory({ equip }: { equip: () => void }): React.Element {
  return <CartoonThemeProvider theme={gameTheme}>
    <Screen ignoreGuiInset={false}>
      <CartoonPanel position={UDim2.fromOffset(24, 24)} size={UDim2.fromOffset(300, 180)}>
        <CartoonText variant="heading" text="Inventory" size={new UDim2(1, 0, 0, 44)} />
        <CartoonButton text="Equip" onActivated={equip} position={UDim2.fromOffset(0, 70)} fullWidth />
      </CartoonPanel>
    </Screen>
  </CartoonThemeProvider>;
}

The provider derives the neutral Core UITheme once per theme reference. Core TextInput and other neutral components beneath it receive common colors, font, spacing, radii and durations. Cartoon components consume additional tokens using useCartoonTheme(). A missing provider raises the existing structured UI_INVALID_CONFIGURATION error.

createCartoonTheme(overrides, base?) merges groups and individual typography roles. Undefined/omitted tokens inherit; zero is preserved. Color3/UDim values stay atomic. Inputs are not mutated. Themes are typed readonly; treat them as immutable after creation. Validation rejects negative/nonfinite numeric tokens, invalid text size ranges and invalid gradient keypoints. defineCartoonTheme(fullTheme) validates a complete theme.

Tokens cover semantic colors, the six original tone colors, per-role typography, radii, borders, hard shadows, spacing, button/icon sizes, gradients and animation timing. colors.primary styles primary buttons; explicit tone="blue" uses tones.blue. Override named tones too when replacing those colors. Font weight comes from Enum.Font; text layout remains native. textSize changes size while retaining the selected role's font/outline.

shared/theme/example-theme.ts supplies oceanCartoonTheme using only color overrides. Component implementations remain the same.

Common layout props: position, size (Icon uses a numeric size), anchorPoint, layoutOrder, zIndex and visible. Native layouts/constraints can be composed as container children. Padding is in pixels. Buttons have small/medium/large heights 44/52/64 and default width 180. Explicit size takes precedence over fullWidth and sizeVariant.

Button variants are primary, secondary, danger, success and ghost. Disabled and loading block activation and GUI selection, including stale pressed/hover state. Loading uses a static ellipsis, replaceable through loadingText. Native Activated supports mouse/touch/gamepad; selection highlights match hover. The original 4 px face press and 5 px hard shadow remain. The lower 3D edge uses the current border color, including hover/selection and pressed highlighting. Position and optional scale overrides transition through the shared presets. Mouse hover and GUI selection are tracked separately, so leaving with the pointer does not erase controller highlighting. The active touch must end before another finger can release it. Temporary InputEnded/WindowFocusReleased listeners exist only during a press and are removed on release, disable/loading or unmount. Mouse leave and gamepad selection loss also cancel their respective press. buttonRef accepts a native TextButton object/callback ref for focus integration.

Icons preserve the original native geometry. Image tint uses white as the neutral multiplier; native tint changes shape fills. Empty image strings fall back to the supplied native name or info. Resolve game image references through RoFrame Assets before passing them; the module bundles no raw asset IDs. Native image load/permission failure handling is not implemented in this milestone.

Data display​

<CartoonCounter value={coins} label="Coins" icon="coin" tone="gold" animated
  onAction={openCollection} />
<CartoonProgressBar value={35} min={20} max={80} label="Progress" showPercentage />
<CartoonBadge text="Ready" variant="success" />
<CartoonStatRow label="Wins" value="1,250" />
<CartoonLoading label="Loading…" />

Counters start from the demo's 236 × 54 counter, 42 px icon and 12 px caption. Compact mode hides the label and uses a 180 × 44 footprint; an action retains the 54 px height to fit a 44 px native button. Values update immediately. Games may pass formatted strings; no currency semantics or optimistic state are added. Optional animation pulses subsequent value changes, including decreases and formatted string changes; first snapshots, unchanged values and nonfinite numbers do not pulse. The .08 s Quad rise to 1.1 comes from the demo; settling uses the theme's normal duration (.28 s by default) and Back easing. The pulse affects only the value, without a reward/gain popup. Coin pickup aggregation and authoritative achievement decisions remain in the demo.

valueContent optionally replaces only the counter's value element, inside its existing value area. The game owns formatting and any custom effect's cleanup and reduced-motion policy. Coin Hunt uses this slot for its gain-only pulse and aggregated +N; the generic counter does not acquire currency/reward semantics. Leave the counter's own animated off when the slot already animates its value.

Progress bars start from the 392 × 21 track and 3 px inset. A label/percentage adds a header. The example above shows 25% because the range starts at 20. The fill clamps to [0, 1]; empty/reversed/nonfinite ranges or nonfinite values display 0%. Finite overruns clamp to the endpoints, including negative ranges and extreme double bounds. Percentages round for display; the fill keeps its precise ratio. Initial state is immediate. Later changes use one native Quad tween over animation.normal; animated=false, animation.enabled=false, or a zero duration applies the target immediately. Setting the value to zero still allows the visible fill to tween down to empty. Its scale-based width tracks parent resizing without polling.

New size tokens include counterWidth/Height/Icon/Label, progressWidth/Height/Inset, badgeWidth/Height, statRowHeight and loadingHeight. Counter pulse amplitude uses animation.valueScale. All inherit through existing partial overrides. Label and value text fit separate available areas; provide enough space for long localized labels and large formatted values. Explicit component size controls the outer footprint; progress headers need vertical space as well as the track.

Badges require text so color is not the sole status signal. Named tones override semantic variants. StatRow is a transparent pair of fitted text columns, with no gameplay state. Loading adds a small static ellipsis motif using existing circles, outlines and tokens; the source demo contained no animated spinner.

Performance and responsive guidance​

See the feedback examples and ownership notes below when adding notifications or modal windows.

  • No polling or frame loops are created. Primitive GUI events remain React-owned; interaction/data/feedback transitions create short native tweens on changes. Toast timers belong to Core's existing queue. Adapter and viewport Signal subscriptions are Cleanup-owned.
  • Cleanup cancels/destroys replaced or unmounted tweens and disconnects completion listeners before cancellation. Completed tweens destroy themselves. Counter pulses keep at most a rise and settle owner per value update and reset scale on replacement/unmount; no tween history accumulates across updates.
  • Only interaction events update button state. Gradients and Core projections use useMemo. Theme creation/validation belongs outside render. No global cache accumulates colors or transient themes.
  • Shadows add one wrapper and one GUI frame. Plain frames do not. Native icons preserve the original small shape trees; image icons are also supported.
  • Buttons keep a stable native TextButton hit target and scale a centered visual frame inside it. Shrinking on press cannot move the pointer outside the hit target.
  • Animated panels add two layout/centering frames and UIScale. Plain panels retain their original tree. Modals share one Core Input binding, one selection listener and one preferred-input listener while present; the last exit/unmount releases all three.
  • Prefer scale widths, native layouts/constraints, safe insets and scrolling. Parent UIScale can shrink a 44 px button below a useful touch size; avoid shrinking entire mobile windows until text and targets become unreadable.
  • animation.enabled=false suppresses press offsets and scale changes and projects Core durations to zero. Counter/progress motion also respects this token. Color and selection feedback remain available.

Animation and controlled panels​

resolveCartoonAnimation(theme, preset, animated?) is exported with CartoonAnimationPreset and CartoonAnimation. It resolves timing/easing without allocating a TweenInfo or starting a tween. Components use the same resolver:

PresetsDuration tokenEasing / direction
hoveranimation.fast (.08 s)Back Out
press, counterRiseanimation.fast (.08 s)Quad Out
release, panelEnter, toastEnter, modalEnter, counterSettleanimation.normal (.28 s)Back Out
progress, fadeanimation.normal (.28 s)Quad Out
panelExit, toastExit, modalExit, fadeExitanimation.exitSeconds (.16 s)Quad In

animated=false, animation.enabled=false or a zero timing applies endpoints immediately without creating native tweens. Button animated=false preserves instant press/scale feedback; the theme's enabled=false suppresses that motion entirely. Default hoverScale/pressScale are 1.035/.94: buttons lift slightly on hover and squash on press, then spring back. Both visual transforms pivot around the button center while its layout footprint and native hit target stay fixed. Games may override them. Counter, panel and modal scale tokens default to 1.1, .9 and .82 respectively. animation.modalOffset (24 px) adds a short upward arrival/downward exit; Back Out produces a small overshoot on entry. animation.slow (.6 s) remains available for game effects such as the demo's floating reward; no permanent effect is attached to it.

For game-owned UI such as a Settings switch knob, the public transitionCartoon(instance, properties, resolveCartoonAnimation(theme, preset)) returns a Cleanup owner. Destroy it on replacement/unmount. Native properties remain typed; completed tweens release themselves. It shares reduced-motion, zero-duration and cancellation behavior with the components.

<CartoonPanel open={inventoryOpen} animated size={UDim2.fromOffset(320, 240)}>
  <CartoonButton text="Equip" onActivated={equip} />
</CartoonPanel>

Panel open defaults to true and animated to false. Opting into animation pops the panel from panelScale to 1 around its center; closing collapses it to zero and then removes the panel. Reopening cancels the pending exit. Closed panels occupy no layout space. Plain panels need neither prop. Panels and modals accept a string/number transitionKey to replay entry when visible content changes, without remounting their focus owner. Keep the component mounted with open=false while it exits: conditionally removing the whole component skips its animation. Panel/modal exit disables descendant CartoonButtons through a private context and blocks pointer activation until removal. Games must disable arbitrary raw/Core/third-party interactive children during exit themselves.

Feedback and overlays​

Own one toast adapter alongside the UI mount, with the same Cleanup owner:

const toasts = cleanup.add(new CartoonToastCenter());

// Inside CartoonThemeProvider and the application's existing Screen:
<CartoonToastProvider center={toasts}>
  <CartoonToastViewport />
</CartoonToastProvider>;

toasts.notify("Saved", { title: "Profile", variant: "success", durationSeconds: 3 });
toasts.notify("+10", { variant: "reward", icon: "trophy" });

Import these names from @frameactive-studio/cartoon-ui. CartoonToastCenter delegates the live list, IDs, capacity and timers to Core NotificationCenter. It adds metadata only: title, icon, close-button preference and the visual reward variant. Reward maps to Core success while using the theme accent and default trophy. Defaults remain Core's four entries/four seconds; duration zero persists until dismissal. Nonfinite/negative explicit durations fail with UI_INVALID_CONFIGURATION.

new CartoonToastCenter(existingCenter) borrows an already configured Core center. Destroying the adapter releases its subscription, Signal and metadata; the supplied center and its timers remain the original owner's responsibility. Without a supplied center, the adapter creates and owns one, destroyed through Cleanup. Its API is notify/list/dismiss/clear/destroy, changed, and readonly .center for Core interoperability. The provider also supplies Core NotificationProvider: existing useNotifications()/Core calls appear with fallback metadata. Rich options are copied and publish atomically after the metadata is ready. Render one viewport per center to avoid duplicate presentation.

Toasts use the counter's slate surface gradient, medium corner radius and solid normal-width ink border (12 px / 3 px in the default theme). The 320 × 58 size and caption font remain. Status colors appear in the title, or the message when no title is supplied. Icons and an optional 44 px X extend the composition. closeButton=false preserves whole-toast dismissal when onClose exists. Width shrinks to the parent safe area, capped by toastWidth. Increase toastHeight for long text; arbitrary messages cannot always fit legibly in 58 px. Standalone CartoonToast owns no timer.

Toasts slide in with Back Out over animation.normal and exit with Quad In over animation.exitSeconds. The viewport retains at most maxExiting removed rows solely for exit presentation. Core remains the live queue owner. Reduced animation/zero exit duration removes rows immediately; native tween completion/interruption/unmount releases resources.

<CartoonModal open={menuOpen} title="Menu" onClose={closeMenu} actions={[
  { text: "Close", variant: "secondary", onActivated: closeMenu },
]}><CartoonText text="Content" wrapped /></CartoonModal>

<CartoonConfirmDialog open={confirmOpen} title="Confirm" message="Continue?"
  onClose={closeConfirm} onConfirm={confirm} busy={pending}
  confirmText="Continue" cancelText="Cancel" />

<CartoonScreenOverlay open={dimmed} transparency={0.55} onActivated={clearDimmed} />

Mount overlays as siblings of screen content, outside scrolling/clipped panels. They cover the entire viewport, including the area behind the top bar and device cutouts. Core's Screen allows this background overflow while keeping modal windows and HUD controls in their normal safe bounds. For a custom ScreenGui, set ClipToDeviceSafeArea={false} and SafeAreaCompatibility={Enum.SafeAreaCompatibility.None}. The parent owns open state; dismissal/actions never silently close or perform gameplay work. Modal open/title/onClose are required; backdrop dismissal and X default on and can be disabled separately. backdrop=false omits the dimmer entirely; back-key policy and focus are still controlled by their own props. The centered slate surface, hard shadow, 63 px gradient title strip and Fredoka heading come from the source window. Defaults are 410 × 420. AbsoluteSize events fit the window plus shadow/header overhang to the safe area, with no minimum scale floor. Content uses a clipped rectangle with an allowance for theme border thickness, hard-shadow offsets and hover growth. Compensating native padding preserves the content's original position and available size, so panels aligned at its edges retain their complete outlines. The scrolling action footer uses the same allowance. Games may compose ScrollingFrame children. Actions are full-width native buttons; long lists use a bounded scrolling footer. Tiny viewports can still shrink text and touch targets; verify game-specific dimensions on devices.

Modal pop (.82→1 plus the 24 px arrival) and backdrop fade use animation.normal. The window springs past its final size briefly; backdrop opacity uses Quad easing. Closing collapses to zero, slides down and fades the backdrop over exitSeconds. Closing blocks pointer activation until removal; reopening cancels pending exit. ConfirmDialog composes the same modal with cancel/confirm actions. busy=true blocks cancel/backdrop/X, Escape and gamepad B and puts confirm into loading state. The game controls async work and closure. Labels can be localized; English confirm/cancel are convenience defaults.

ScreenOverlay uses the theme background and overlay.transparency (.55). Prop opacity clamps to [0, 1]; invalid nonfinite values are transparent. With blocksInput=false it renders a visual frame without a button input surface. Closed overlays hide and release input capture after fading. All motion respects animation.enabled and zero duration. New tokens include toastWidth/Height, modalWidth/Height/HeaderHeight, animation.modalScale and overlay.transparency. No camera effect, blur or permanent animation timer is added.

Modal focus and back input​

CartoonButton, selectable toasts and modal fallback selection use four rounded white corner brackets with a thin ink outline. The sides stay open. Colors follow textPrimary/border. All four corners mirror one rounded path; arm length, gap and line width adapt to the control's shorter screen dimension. Rounded capsules draw the white path over a separate ink silhouette, including outlined round end caps. The outline stays at least 1.5 screen pixels wide. No clipped UIStroke is used.

Only the selected control creates a CartoonFocusOverlay ScreenGui under PlayerGui, with DisplayOrder 2147483647 and Global ZIndexBehavior. It sits above game UI and escapes parent clipping, padding and sibling stacking. Roblox CoreGui retains its own layer. A transparent, childless SelectionImageObject suppresses the default frame. SelectionGained/SelectionLost drive visibility; absolute position, size and rotation events keep the overlay aligned without a frame loop or new input binding. Source screen insets are respected. Hidden ancestors, disabled screens/controls, loss of selection and unmount destroy the active overlay. Buttons follow their animated visual bounds and include the scaled lower shadow. Selected buttons keep their ink border so the corners provide the focus outline.

For custom selectable controls, place <CartoonFocusCorners /> directly inside their native GuiObject, including inside Core TextInput's children slot. An optional bottomOffset includes a custom lower shadow; boundsRef can follow a separate animated GuiObject while selection stays on the native control. Unmount/theme changes restore the previous SelectionImageObject when still owned, disconnect listeners and destroy overlay and suppression object. Mounting an already selected control shows the corners immediately; becoming non-selectable hides them. The demo applies this to collection cards, switches and admin text fields too.

Modals use Roblox GUI selection for navigation. Native SelectionGroup with Stop in all four directions confines directional selection to the window. By default, automatic selection runs only for gamepad/MicroGamepad preferred input. Keyboard and touch do not acquire GUI navigation. Switching back to keyboard/touch clears selection acquired inside the modal; switching to gamepad selects a control. This is event-driven through UserInputService.PreferredInput. Explicit autoFocus=true opts into automatic selection on all devices, while autoFocus=false leaves selection to the game on every device. When automatic selection is active, initialFocus selects a valid visible/selectable descendant, otherwise GuiService.Select chooses one using native selection order. Footer actions have increasing SelectionOrder and the X follows them, so the confirm dialog's cancel action comes before confirm. With no enabled control, the window itself is the fallback. No custom arrow-navigation engine is introduced.

const cancelButton = React.useRef<TextButton>();
// Inside the component's return:
<CartoonModal open={open} title="Inventory" onClose={close} initialFocus={cancelButton}
  actions={[{ text: "Cancel", variant: "secondary", onActivated: close, buttonRef: cancelButton }]} />

Each present modal leases the shared input/focus owner. The highest ScreenGui DisplayOrder, then modal zIndex, then newest mounted modal owns back input. dismissOnEscape and dismissOnGamepadBack default to true; Begin invokes the top owner's onClose once. A busy, closing or non-dismissible top window consumes the action without closing a parent. TextBox focus passes the action through to native text input. The game still owns open; handlers never mutate it.

On exit completion/unmount, selection returns to the valid caller or the next visible modal when automatic selection is active. Keyboard/touch restoration does not reactivate a selection inherited from a previous controller session. Removed/hidden/disabled targets are skipped, including when a parent unmounts before its child. A valid selection explicitly moved outside the modal by the game is preserved under the default restoreFocus=true policy. Game menus can set restoreFocus=false to clear GUI selection when the final window closes, returning control to gameplay even if Roblox moved selection to a HUD sibling during unmount. Nested dialogs still return to their visible parent. Selection/input-mode events and React updates refresh focus; there is no polling. The binding exists only while windows are present and uses the existing Core Input API without creating a touch button.

ContextActionService dispatch depends on binding order and priority (see the Roblox reference). System-menu interaction, especially Escape, and competing game bindings still require native validation. The module does not override Roblox system controls.

To inspect the gallery, import it in development-only client code and mount through the already-registered UIController after awaiting startup:

import React from "@rbxts/react";
import { RoFrame } from "@frameactive-studio/core";
import { UIController } from "@frameactive-studio/core/ui";
import { CartoonUIShowcase } from "@frameactive-studio/cartoon-ui/showcase";

// After awaiting startClient, with the module enabled:
if (RoFrame.isModuleEnabled("cartoon-ui")) {
  RoFrame.getController(UIController).mount("CartoonUIShowcase", <CartoonUIShowcase />);
}

UIController owns the mount until unmount/runtime shutdown. The gallery is not mounted by default and does not alter Coin Hunt. It vertically scrolls the same primitive/data-display composition in default and Ocean themes. Each section has independent +10/−10/Reset controls, a counter action, compact/formatted counters, a 20–80 range, empty/full tracks, semantic badges, StatRow and Loading. The Value motion switch disables the counter/progress/panel animations in that section; button interaction is still active.

Both theme sections expose toast variants, persistent/burst/clear actions, modal, confirm and dimmer controls. Feedback mounts at Screen level, outside the scroller. The active theme follows the section used to open feedback. Gallery teardown destroys its adapter and owned Core timers. Each section also has a controlled panel enter/exit example and a button with immediate press feedback. The modal contains a neutral Core TextInput, explicit initial focus and a nested confirm action to inspect focus restoration.

Manual checklist — not yet executed in Studio:

  1. Build/sync and mount the gallery. Compare Fredoka font, outlines, gradients, shadows and coin geometry with the existing demo.
  2. Activate all five variants with mouse/touch/gamepad. Count advances once per activation; disabled/loading buttons never increment it.
  3. Move controller selection and release presses outside the button. Verify highlighting, resetting press state, and disabling while pressed/selected. Release a second finger first and move window focus away during a press.
  4. Inspect both themes and the modal's neutral Core TextInput for shared tokens.
  5. Resize desktop/tablet/portrait/landscape. Check scrolling, text fitting, touch targets and Roblox's top inset.
  6. Change data values rapidly and use Reset. The counter text updates immediately, pulse settles to 1 and the progress fill reaches the latest target. Empty/full tracks, compact counter, text-only counter, badges and loading remain readable.
  7. Disable value motion midway through a transition; counter settles, fill snaps to the controlled target, and later changes remain instant. Also test an animation.enabled=false theme and zero normal duration.
  8. Unmount during a pulse/fill transition, remount and stop Play. Verify no duplicate roots, orphaned tweens, late callbacks or lingering handlers.
  9. Cycle all five toast variants. Check title/message/icon/X, timed dismissal, persistent duration zero and Clear. Burst 20: Core retains four live entries, and the viewport at most four exit rows.
  10. Open/close the modal with X, backdrop and footer. Clicking content must not dismiss it. Resize and test many actions in the scrolling footer. Confirm and cancel through the dialog; test busy=true by driving the controlled prop.
  11. Reverse fade/pop rapidly and unmount during exit. Disabled/zero-duration animation applies targets immediately. Closed overlays capture no input; blocksInput=false must let underlying GUI receive pointer input.
  12. Verify touch/controller activation for toast X and modal actions. Open a modal from a selected caller, navigate all four directions and check initial focus. Open nested confirm and dismiss with B/Escape; only the top dialog closes and focus returns to its caller after exit. Check native system-menu interaction.
  13. Focus the TextInput before B/Escape. Verify native text behavior, busy and non-dismissible dialogs, autoFocus=false, hidden/disabled targets and a parent unmounted before its child. After the final unmount, inspect that the Core action and selection/release listeners are gone and game input works normally.
  14. Rapidly reverse panel entry/exit, activate during exit and unmount midway. Test custom hoverScale/pressScale, reduced motion and zero fast/normal/exit timings.
  15. In Coin Hunt, close through Play/X/backdrop/M/B and reopen during the exit. The last page must remain visible until the shrink finishes, with no active exit controls, stale tweens, duplicate input owners or persistent HUD focus. Switch pages, select milestones, toggle Settings rapidly and click button edges while they squash; targets remain stable and outlines remain complete.

Studio's connected edit-time place did not have the new display-model file synchronized during Phase D, so no native logic/render/input test is claimed. Build/sync the latest output before executing the checklist.
