Cartoon UI audit

Source of truth: the existing Coin Hunt UI, inspected before module implementation on 2026-10-15. This is a source audit; native Studio rendering has not been verified during this milestone. The neutral Phase 8 UI is infrastructure, not a replacement visual reference.

The source paths below describe the pre-migration audit. Phase G removed the former demo/client/ui/cartoon.tsx; the extraction/migration mapping is retained here as the visual baseline rather than as an inventory of current files.

Fredoka One supplies the weight; there is no separate font-weight or line-height engine. Text uses Roblox sizing constraints. Exposed typography presets allow each role's font, size and stroke to change. Additional sizes (small/large buttons, generic image icon) are missing primitives derived from these values, not a new visual direction.

Interaction and motion​

  • Idle buttons: gradient face and fixed shadow. Hover/GUI selection: 15% paper highlight and paper border. Press: face moves down 4 px. Mouse leave and selection loss clear press state. Disabled: gray face; activation and selection disabled. Existing buttons have no loading state; the module adds a static ellipsis and blocks activation without a permanent animation loop.
  • Native Activated supports mouse/touch/gamepad; SelectionGained/Lost reuse hover appearance. UI routing and M/D-pad Up bindings stay in the demo/Core.
  • Modal backdrop: ink at .55 transparency; click dismisses. The window itself consumes input. No entrance/exit animation exists in the source windows.
  • Coin feedback: .08 s Quad pop to 1.1, .24 s Back settle, .6 s float/fade over 16 px. Initial balance and spending do not trigger it. Cleanup cancels previous bursts and releases tweens and completion connections.
  • Notifications use one-shot scheduler delays (demo: three entries, three seconds; achievement: five seconds). No toast enter/exit animation exists yet.
  • No tooltip, tabs, side navigation framework, badge component, loading spinner or image icon assets exist. Do not claim these were extracted from the demo.

Layout and responsive behavior​

  • Windows fit available dimensions using min(1, (width-32)/panelWidth, (height-32)/panelHeight) with an existing .1 lower clamp.
  • HUD scale uses width/1100 and height/650, capped at 1 with .6/.65 floors.
  • At width <700 the logo anchors right and the menu moves to the top right; the notification stack moves below it. Viewport AbsoluteSize events drive changes. ScreenGui respects Roblox's inset.
  • Collection uses a fixed card row plus right detail pane; scaled as a whole. The current lower scale clamps can make text/touch targets small or overflow extremely tiny viewports. Treat this as a later responsive-validation item, not evidence of verified accessibility on every device.
  • Roblox layouts/constraints remain preferred; no custom layout or focus engine.

Demo-specific behavior​

Coin balance, lifetime pickups, Collector I, thresholds 1/5/10/25, persisted achievement flags, admin commands, profile readiness, round pause, localization keys, audio preferences, pickup popup aggregation and menu destinations stay under demo/src/demo. The module owns only presentation and interaction primitives.

No GUI image IDs need migration: icons are native shapes. Demo audio assets belong to the gameplay demo and do not become Cartoon UI dependencies.

Integration decisions​

The generic UITheme lacks cartoon borders, shadows and per-role typography. Use one cartoon context for those extra tokens and project its common values into the existing Core ThemeProvider. Core components (for example TextInput) then share the same theme without importing the optional module. UIController continues to own roots; NotificationCenter, Cleanup and native GUI selection remain the infrastructure.

The optional manifest uses the actual defineModule API. Its shared entry imports no React or client code. Explicit registration is supported by RoFrame; the primitive milestone adds no automatic demo registration or UI mount. Module enablement controls lifecycle; mounting consumers must also follow the game's activation choice because Core starts Controllers before module hooks.

Phase D additions​

Counter and progress dimensions, inset and counter caption size are now theme tokens. The action button uses a 44 px target; the normal counter footprint stays 236 × 54. Counter motion is an optional generic change pulse with the demo's .08/.24 second timing and 1.1 scale, without coin-specific gain aggregation. Progress transitions use a bounded native tween and no per-frame React state.

Badge, StatRow and Loading fill gaps in the source UI. Badge reuses existing outlined pill shapes, semantic colors and caption text; StatRow pairs existing text roles in two columns; Loading uses three static outlined circles with an optional localized caption. These are new compositions of audited primitives, not claims that the demo contained a badge component or spinner. The expanded gallery demonstrates them under both default and Ocean tokens. Demo migration remains Phase G.

Phase E additions​

The source window maps to CartoonModal's slate body, hard shadow, rounded gradient title strip and close action. The backdrop's .55 transparency is now a theme token and reusable ScreenOverlay. ConfirmDialog composes the modal without gameplay or async ownership. Modal safe fitting includes shadow/title overhang and removes the source's .1 lower scale clamp; native viewport events drive sizing. Footer actions and tiny-view/long-content behavior still need visual device validation.

CartoonToastCenter decorates the existing Core queue with title/icon/reward metadata. Core still owns limits, IDs and one-shot timers. Toast presentation keeps the audited surface and outline, adds an optional 44 px X, and retains a bounded number of removed rows for native exit slides. Pop, slide and fade are small new discrete transitions; they did not exist in the original windows/toasts. They use theme timing and Cleanup, with no render loop or new animation runtime. The gallery demonstrates each under both themes. Native hit testing, focus and input behavior remain manual checks.

Phase F additions​

Shared presets now drive button hover/press/release, panel pop, modal pop, toast slide, progress, counter pulses and overlay fades. The source's press offset and counter easing/timing remain; hoverScale/pressScale default to 1. Panel pop (.97) is an optional new transition for a source gap. Zero/reduced motion applies targets without allocating tweens. Every transition uses Cleanup and cancels on replacement.

Button mouse hover and GUI selection are independent. A press owns temporary release/window-focus listeners; touch release matches the original finger, and disable/loading/unmount releases ownership. Native Activated remains the callback.

Modal focus uses GuiService.Select, native selection groups/order and valid caller restoration. One shared Core Input binding handles Escape/B while any modal is present. Layer priority, busy/exit consumption, text focus and out-of-order teardown are covered by injected-port logic tests. Native dispatch, system-menu priority and device navigation still need Studio testing. The gallery adds animated panels, a Core TextInput and nested confirm for that purpose.

Phase G migration​

Coin Hunt now imports the public Cartoon UI API directly. The duplicate text, icon, button, surface, shadow, gradient and window implementations in its old cartoon.tsx are removed. The HUD uses CartoonCounter, its bottom track uses CartoonProgressBar, and all windows use CartoonModal. Selected milestone borders and switches remain demo compositions over CartoonCard/Frame and native buttons; no inventory or settings subsystem was introduced in the module.

The counter's optional valueContent slot preserves the demo's gain-only pulse, gold flash and aggregated floating +N. Native effect refs use theme typography and colors. That effect, Store subscriptions, localization, milestone selection, settings, admin requests and coin rules stay under demo/src/demo.

The demo explicitly registers/enables the manifest in client bootstrap and gates the UI with the same flag. Toast presentation borrows the existing Core queue, retaining its three-entry capacity and three/five-second lifetimes. Most former instant transitions opt out of module motion. D-pad Up now passes through while windows are open so native selection can move upward; B closes the modal.

Window dimensions, sidebar positions and HUD scale retain the source layout. Module safe fitting includes overhang and removes the old scale floor. The X is a standard 44 px target; counter geometry, toast insets and Core TextInput adopt the common tokens. Source/type/build checks cover this migration; pixel alignment, clipping, native focus and device behavior still require the documented Studio comparison. No native visual equivalence is claimed yet.

Cartoon motion pass​

Following the request for livelier motion, the source's instant interaction is now deliberately extended: .28 s Back Out entrances/rebounds, .16 s Quad In exits, .82 modal scale with a 24 px arrival, .9 panel scale, and 1.035/.94 hover/ press button scales. Colors, outlines, native icons and hard-shadow geometry keep their audited identity; the shadow still matches the current button border.

Button input stays on a fixed native TextButton while only the centered visual frame moves. This prevents squash feedback from cancelling edge clicks. The modal clipping allowance includes hover growth. Demo windows retain their last page while exiting, disable exit actions, and use transitionKey to pop between pages without replacing the focus owner. Collection details and Settings knobs also animate. Progress/counter/toast motion is enabled in the demo; the gain-only coin effect retains its separate existing rules and timing.

Motion remains discrete, theme-controlled and Cleanup-owned, with no frame loop. Reduced/zero motion and rapid replacement are covered by preset/tween tests; page retention is checked as a composition contract. Native feel, edge clicking, focus and clipping under rapid reversals still require the Studio checklist.

Notification surface alignment​

Following the request to match the coin display, toasts now share the counter's slate CartoonShine gradient, medium corners and normal ink outline. Status color moves from the outer border to the title or untitled message. Queue ownership, duration, dismissal, dimensions and slide transitions remain unchanged.

Controller focus corners​

Native selection now uses four rounded white brackets with a thin ink outline, leaving the sides open. The initial nested SelectionImageObject template was invisible in Studio despite a selected gamepad control. Brackets now live in the real GUI tree and follow native selection events; a childless transparent native adornment suppresses the default frame without changing navigation/input ownership. Buttons include their hard shadow; modal clipping allowance includes the brackets. Collection cards, switches and Core text inputs in the demo use the same public CartoonFocusCorners composition.

The corrected ordinary-GUI composition was verified in the active Studio client: gamepad preferred input selected the main-menu Play button, and a viewport capture showed all four white outlined corners. Selected button borders now stay ink so the old full white outline does not compete with the brackets. A regression test covers real-tree parenting, initial selection, gain/loss, disabling, restoration and connection/instance cleanup.

The subsequent symmetry/layering pass replaces clipped rounded rectangles with one mirrored curved path, drawn as white rounded capsules over an ink silhouette. Only the selected control owns an overlay ScreenGui at DisplayOrder 2147483647, outside source clipping/padding and sibling stacking contexts. Screen-space bounds and UI scale position the brackets around the animated button plus its shadow. Geometry tests cover small, square, wide and tall controls; native-port tests cover overlay reuse during bounds changes, hidden/disabled ancestors, focus lifecycle and complete cleanup. Active Studio captures verified the long Play button, collection cards and small modal X, including its corners above the title strip.
