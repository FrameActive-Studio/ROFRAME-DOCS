Cartoon UI: Shop & Monetization

Die Kategorie SHOP im gemeinsamen Storybook enthält einen Beispielshop und je eine Seite für ShopCard, ProductCard, PurchaseButton, PurchaseDialog, PriceTag, OwnedBadge und OfferBanner. Alle sieben werden einmal in src/shared/platform/shop.ts definiert und von Roblox und React Web verwendet. Die kurzen Namen und die Varianten mit Cartoon-Präfix sind identische Exporte.

KomponenteVerwendung
ShopCardProduktgruppe mit farbigem Kopf, Icon, Untertitel und eigenem Inhalt
ProductCardArtikel mit Bild/Cartoon-Icon, Menge, Beschreibung, Preis und Kaufbutton
PurchaseButtonKaufaktion mit Lade-, Kauf-, Besitz- und Nicht-verfügbar-Zustand
PurchaseDialogBestätigung mit Artikelvorschau, Preis, Fehler und zwei Aktionen
PriceTagFormatierter Katalogpreis, optionale Währung und durchgestrichener vorheriger Preis
OwnedBadgeBesitzanzeige, optional mit eigenem Text
OfferBannerHervorgehobenes Paket mit Beschreibung und optionalem Aktionsbutton

Einbinden​

import { ShopCard, ProductCard, PurchaseDialog } from "@frameactive-studio/cartoon-ui";

// Unter CartoonThemeProvider; dieselbe Komposition auf beiden Plattformen.
<ShopCard title="Münzpakete" icon="coin" tone="gold">
  <ProductCard
    title="Kleine Münztruhe"
    quantity="500 Münzen"
    description="Für dein nächstes Abenteuer."
    icon="coin"
    artwork="small"
    price={catalogPrice}
    currency="Robux"
    owned={isOwned}
    status={catalogLoading ? "loading" : "ready"}
    onPurchase={() => setDialogOpen(true)}
  />
</ShopCard>

<PurchaseDialog
  open={dialogOpen}
  title="Kleine Münztruhe"
  price={catalogPrice}
  currency="Robux"
  status={purchaseStatus}
  error={purchaseError}
  onClose={() => setDialogOpen(false)}
  onPurchase={requestPurchase}
/>

price ist ein bereits formatiertes String-Ergebnis deines Katalogs. Es wird weder eine Währung umgerechnet noch ein Preis aus einer Produkt-ID geschätzt. currency ergänzt die Einheit; currencyIcon ist ein optionales Cartoon-Icon. originalPrice zeigt einen separat gelieferten vorherigen Preis durchgestrichen. Ein fehlender oder leerer Preis sperrt den Kauf; "0" ist ein gültiger Preis.

status ist ready, loading, purchasing, owned oder unavailable. owned hat Vorrang, loading kann zusätzlich als Boolean gesetzt werden. Bei purchasing sperrt der Dialog Kaufen, Abbrechen, Escape und das Schließen-X. Ein Fehlertext lässt sich mit erneutem Status ready zusammen anzeigen. Status und Besitz werden vom Consumer kontrolliert; die Komponenten bestätigen keinen Kauf selbst. onPurchase verbindet die UI mit deinem Kaufsystem. Setze owned erst, nachdem dein Spiel den Besitz bestätigt hat.

image ersetzt die Illustration einer Produktkarte oder des Dialogs. artwork="small" | "large" | "mega" wählt eine der mitgelieferten transparenten Truhen. Dieselben PNGs liegen unter src/assets/shop, sind im Web eingebettet und über feste Roblox-Bild-IDs verfügbar. Eigene Assets können in Roblox mit configureCartoonShopAssets hinterlegt werden. Die Bildgenerierungs-Prompts stehen neben den PNGs in PROMPTS.md. tone, ribbon und featured steuern Farbe, Kennzeichnung und die größere Produktdarstellung. label, confirmLabel und cancelLabel erlauben eigene Aktionsbeschriftungen. ShopCard.children kann ein CartoonGrid, eine Liste oder eigener Inhalt sein. In einem Grid bestimmt cellHeight die Kartenhöhe; reguläre Produktkarten sind standardmäßig 410 px hoch, hervorgehobene 440 px. Ein vorheriger Preis erhält jeweils 26 px zusätzlich. Die Illustration passt sich an die tatsächliche Kartenhöhe an; plane Platz für den festen Schatten ein.

Die Karte hebt sich beim Hover leicht und die Illustration wippt einmal mit. Ein Übergang zu owned löst einen einmaligen, 1,05 Sekunden langen Münzflug mit Häkchen-/Erfolgsanzeige aus; bereits beim Mount besessene Artikel feiern nicht erneut. rewardAmount ist eine optionale Zahl für den hochzählenden Beleg im Effekt und wird vom Consumer geliefert. animated={false}, deaktivierte Theme-Animationen und reduzierte Bewegung unterdrücken die Bewegung. Timer und Frame-Callbacks werden bei Statuswechsel und Unmount freigegeben. Animationen bleiben im gemeinsamen Code; die Adapter enthalten keine eigenen Shop-Timelines.

Der Dialog passt sich an den Viewport an und scrollt seinen Inhalt bei wenig Höhe. Seine optionale size ist in Roblox ein Vector2, im Web ein [width, height]-Tupel. Andere Shop-Komponenten nutzen die üblichen Layout-Props.

Vorschau​

npm run storybook:web startet die Web-Galerie. Die Roblox-Galerie wird mit npm run storybook:build erzeugt. Unter SHOP / Shop & Monetization kann ein Demo-Kauf vollständig durchgespielt werden. Unter PurchaseDialog lässt sich ein fehlgeschlagener Kauf simulieren. Beispielpreise und Käufe sind lokal simuliert. Es werden weder Robux ausgegeben noch echte Produkte erworben.
