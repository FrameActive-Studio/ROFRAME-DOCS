Cartoon UI für React-Web und Roblox

@frameactive-studio/cartoon-ui enthält zwei Renderer in einem Paket. Die gesamte Komponentenstruktur, Geometrie, Darstellung und Interaktionslogik liegt einmalig unter src/shared/platform/components.ts. Auch Storybook und Vergleichsansicht werden einmalig in gallery.ts definiert. Die Adapter übersetzen ausschließlich Host-Elemente, Hooks und native Ereignisse. Der Web-Einstieg lädt weder Roblox-Globals noch Core.

Installation und Einstiege​

Wechsel von 1.x auf 2.0​

Aktualisiere @frameactive-studio/cartoon-ui auf ^2.0.0. Bestehende roblox-ts- Importe und native Layout-Props bleiben gültig. Die Paketwurzel verwendet nun bedingte Exporte für React-Web und Roblox; Werkzeuge, die package.json#exports selbst auswerten, müssen verschachtelte import-/require-Einträge und die CSS-/Bild-Unterpfade unterstützen. Verwende bei Bedarf /web oder /roblox. Installiere die React-Peers deiner Zielplattform ausdrücklich und binde im Web einmal @frameactive-studio/cartoon-ui/styles.css ein. Die überarbeiteten Farben, Schriften, Abstände und Animationen gelten auf beiden Plattformen.

Das Paket bleibt im bestehenden GitHub-Packages-Registry. Konfiguriere den Scope und authentifiziere dich wie unter Packaging.

npm install @frameactive-studio/cartoon-ui

Alle Plattform-Peers sind optional, damit npm nicht beide React-Runtimes lädt. Installiere die Peers deiner Zielplattform ausdrücklich:

ZielZusätzlich benötigte PaketeEinstieg
React-Webreact, react-dom (18.2 oder 19)Paketwurzel oder /web
Roblox@frameactive-studio/core, @rbxts/react, @rbxts/react-robloxPaketwurzel mit roblox-ts oder /roblox

Moderne Web-Bundler und TypeScript mit moduleResolution: "bundler", "node16" oder "nodenext" wählen automatisch die Web-Ausgabe. ESM und CommonJS haben eigene JavaScript-Dateien und Typdeklarationen. Bestehende roblox-ts-Projekte behalten über main, types und typesVersions den Luau-Renderer. Ältere Web-TypeScript-Projekte mit moduleResolution: "node" verwenden ausdrücklich @frameactive-studio/cartoon-ui/web.

Gemeinsame Komponenten statt zweier Implementierungen​

src/shared/platform/components.ts   Komponenten, Zustände, Farben, Abstände
src/shared/platform/shop.ts         Shop-Kompositionen und Kaufanimationen
src/shared/platform/gallery.ts      Storybook und feste Vergleichsansicht
src/shared/platform/text-layout.ts  Gemeinsame Glyphenpositionen und Umbrüche
src/client/platform/adapter.tsx     Roblox-Instanzen und native Ereignisse
web/adapter.tsx                     DOM-Elemente und Browser-Ereignisse

Eine neue Komponente wird ausschließlich in createCartoonComponents ergänzt. Die öffentlichen Dateien unter client/components und web exportieren nur plattformspezifisch typisierte Bindings. CSS enthält Host-Resets; Button-, Formular- und Modalgestaltung werden nicht zusätzlich in CSS implementiert.

Die gemeinsame Maßeinheit ist ein logisches Pixel. size, position und anchorPoint lassen sich im Web als neutrale Strukturen angeben; in Roblox bleiben bestehende UDim2-/Vector2-Props gültig. style ist eine zusätzliche Web-Schnittstelle; eigene CSS-Overrides verändern natürlich die Darstellung.

const dimensions = { x: { scale: 1, offset: 0 }, y: { scale: 0, offset: 52 } };

Sichtbarer Text verwendet dieselben mitgelieferten Fredoka-Glyphenbilder, Advances und Zeilenumbrüche. Native Eingabeelemente bleiben für Bearbeitung, Passwortmaskierung, Barrierefreiheit und Formularvalidierung vorhanden; ihre sichtbare Darstellung entsteht in der gemeinsamen Komponente. Eine feste Vergleichsansicht (CartoonUIParityScene aus /storybook) prüft beide Hosts bei denselben Maßen. Im lokalen Browser: ?parity=1 (640 × 600 logische Pixel).

Glyphenbilder und Buchstabenabstände verwenden denselben Skalierungsfaktor; alle Schriftkonturen liegen hinter sämtlichen Buchstaben. Monospace-Zellen berücksichtigen auch breite Zeichen. Button-Icons richten sich nach der tatsächlichen Buttonhöhe und nutzen Ankerpunkte zur Zentrierung, auch in skalierten Containern.

Beide Adapter vererben Transparenz direkt an Flächen, Konturen und Bilder. Der Roblox-Renderer verwendet dafür keine CanvasGroup: Deren zusätzliche, von der Grafikqualität abhängige Zwischentextur würde gerade im Vollbild-Boot die Schrift erneut skalieren und unscharf machen.

Schriftatlanten in Roblox​

Das Paket enthält feste Roblox-Image-IDs für die beiden gemeinsamen Atlanten. Eine normale Installation braucht weder einen eigenen Upload noch EditableImage oder eine zusätzliche Sicherheitseinstellung. Der Web-Build bettet dieselben PNG-Dateien lokal ein. Mit configureCartoonFontAssets({ fill, outline }) können Projekte eigene, identisch erzeugte Atlanten einsetzen.

npm run fonts:build --workspace @frameactive-studio/cartoon-ui erzeugt PNGs, Web-Daten und Glyphenmetriken aus derselben Schriftquelle. Nach Änderungen müssen die beiden PNGs erneut hochgeladen und die Standard-IDs aktualisiert werden. Schriftwechsel benötigen ebenfalls passende Atlanten für beide Hosts.

React-Web verwenden​

npm install react react-dom
npm install -D @types/react @types/react-dom # bei TypeScript

Importiere die Styles einmal am Einstieg deiner Webseite. Die Schrift wird lokal mitgeliefert; es gibt keine Anfragen an externe Font-Dienste.

import { useState } from "react";
import {
  CartoonThemeProvider, CartoonForm, CartoonInput, CartoonCheckbox,
} from "@frameactive-studio/cartoon-ui";
import "@frameactive-studio/cartoon-ui/styles.css";

export function Profile() {
  const [name, setName] = useState("");
  const [music, setMusic] = useState(true);
  return (
    <CartoonThemeProvider>
      <CartoonForm onSubmit={() => console.log({ name, music })}>
        <CartoonInput label="Name" name="player" required
          value={name} onValueChanged={setName} />
        <CartoonCheckbox label="Musik" checked={music} onChanged={setMusic} />
      </CartoonForm>
    </CartoonThemeProvider>
  );
}

Web-Komponenten unterstützen className, style, id und passende native Formularattribute. Passwortfelder sind echte <input type="password">. Select/DropdownButton bieten eigene Popovers, Pfeiltasten, Home/End, Escape und Fokus-Rückgabe. Modals halten den Tastaturfokus im Dialog. Animationen berücksichtigen das gemeinsame Theme (animation.enabled: false für reduzierte Bewegung).

SSR-Imports greifen nicht auf Browser- oder Roblox-Globals zu. Interaktive Komponenten sind mit "use client" markiert. In Next.js gehören Zustände und Handler in eine eigene Client-Komponente; die CSS-Datei kann im Layout liegen. Portals werden erst nach dem Mount angelegt. RelativeTime akzeptiert optional now in Unix-Sekunden für eine feste, reproduzierbare Serverausgabe.

Roblox weiterverwenden​

import React from "@rbxts/react";
import { CartoonThemeProvider, CartoonButton } from
  "@frameactive-studio/cartoon-ui";
// Explizit ebenfalls möglich: @frameactive-studio/cartoon-ui/roblox

const view = <CartoonThemeProvider>
  <CartoonButton text="Spielen" onActivated={() => print("Start")} />
</CartoonThemeProvider>;

Rojo lädt weiterhin nur out/ über default.project.json. Die Web-Ausgabe unter dist/ wird nicht ins Spiel eingebunden. Der serverseitig sichere Moduleinstieg bleibt /module; der native Boot nutzt weiterhin Core und mountBootScreen.

Gemeinsame API und native Layoutwerte​

Beide Renderer bieten Text, Icon, Button, ButtonGroup, Frame, Panel, Card, Checkbox, Radio, Input, InputGroup, Form, Select, DropdownButton, Tabs, RelativeTime, List, Grid, ScrollBox, Loading, ProgressBar, Counter, Badge, StatRow, Modal, ConfirmDialog, ScreenOverlay, Toasts und BootScreen.

Verhaltensprops wie onActivated, onValueChanged, onChanged, value, checked, disabled und loading bleiben gleich. Layout und Farben sind plattformspezifisch: CSS-Werte im Web, UDim2, Vector2, Color3 und Enum in Roblox. DOM- und React-Lua-Elemente können nicht ineinander eingesetzt werden. Nutze den Provider des jeweiligen Renderers.

ProgressBar verwendet auf beiden Plattformen min=0, max=100; RelativeTime erwartet Unix-Sekunden. createCartoonTheme akzeptiert im Web CSS-Farbstrings und Pixelzahlen. Die Roblox-Projektion derselben cartoonTokens erzeugt Color3, UDim und Enum.Font.

Bootscreen im Web​

Der Browser bekommt den Fortschritt aus deiner Anwendung, ohne Roblox-Core. Alternativ zu kontrollierten Props unterstützt er einen CartoonBootSource mit read() und changed.connect().

import { CartoonBootScreen } from "@frameactive-studio/cartoon-ui";
import logo from "@frameactive-studio/cartoon-ui/logo.png";

<CartoonBootScreen gameName="Cartoon UI" progress={0.4} stage="Daten laden …"
  loading={true} branding={{ logo, showPoweredByRoFrame: true }}
  loader={{ showProgress: true, showPercentage: true, showStage: true }} />;

Boot-Fortschritt liegt zwischen 0 und 1. loading={false} entfernt den Screen. Der PNG-Import benötigt die übliche Asset-Unterstützung deines Web-Bundlers; alternativ übergib eine Bild-URL aus deinem Projekt. Für Demos gibt es createCartoonBootSequence(10) im Web-Einstieg.

Galerien und Tests​

npm run storybook:web   # http://127.0.0.1:6016, automatische Rebuilds
npm run storybook:build # native Roblox-Galerie
npm run storybook:serve # Rojo auf Port 34873
npm run build --workspace @frameactive-studio/cartoon-ui # beide Renderer
npm run test:cartoon-web # nach dem Build

CARTOON_UI_WEB_PORT überschreibt den Browser-Port. Im eigenen React-Projekt kannst du CartoonUIStorybook aus /storybook oder /web/storybook importieren und zusammen mit der CSS-Datei rendern.

Die Tests installieren das echte Paketarchiv in einer isolierten Webseite und prüfen TypeScript, Browser-Bundle, ESM-/CommonJS-SSR und fehlende Roblox-Peers. Der native Consumer prüft weiterhin TypeScript, roblox-ts und Rojo.
