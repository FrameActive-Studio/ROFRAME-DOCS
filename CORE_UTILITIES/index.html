Phase 9 Core Utilities

Phase 9 adds small, independent utilities on top of Roblox-native APIs. None of these systems starts a permanent polling loop, creates gameplay state, or replaces Roblox Instances and services.

All public values and types are exported from packages/core/src/index.ts.

Scheduler​

Scheduler owns cancellable task.delay, repeated delays, cooldown timestamps, and optional RunService.Heartbeat connections. Named tasks replace an older task with the same name.

import { Cleanup, Scheduler } from "@frameactive-studio/core";

const cleanup = new Cleanup();
const scheduler = cleanup.add(new Scheduler());

scheduler.delay(2, () => print("ready"), "ready-message");
scheduler.every(30, () => print("autosave"), "autosave");

if (scheduler.cooldown("dash", 1.5)) {
	print("dash accepted");
}

Use heartbeat only for work that genuinely needs per-frame updates. destroy() cancels every owned task and connection.

State machine​

State and transition names are string unions. Guards run before exit/enter hooks; successful transitions emit changed.

type State = "lobby" | "playing" | "results";
type Transition = "start" | "finish";

const rounds = defineStateMachine<State, Transition, { players: number }>({
	initial: "lobby",
	context: { players: 0 },
	states: { lobby: {}, playing: {}, results: {} },
	transitions: {
		start: { from: "lobby", to: "playing", guard: (context) => context.players > 0 },
		finish: { from: "playing", to: "results" },
	},
});

rounds.transition("start"); // false when the guard rejects it
rounds.require("finish"); // throws a structured error when invalid

Assets​

Asset keys are inferred from one central map. Values may be content ID strings or Instances. Preloading delegates to ContentProvider.PreloadAsync.

const Assets = defineAssets({
	"Sounds.Click": "rbxassetid://123",
	"Images.Coin": "rbxassetid://456",
});

const clickId = Assets.get("Sounds.Click");
await Assets.preload(["Sounds.Click"]);

Only put an Instance in a shared registry when that Instance is replicated to both runtimes.

Localization​

Localization delegates formatted translations to Roblox Translator and uses explicit project fallbacks until a translator is loaded or when a key is missing.

const Locale = defineLocalization({
	"UI.Play": "Play",
	"UI.Settings": "Settings",
});

await Locale.useLocale(game.GetService("LocalizationService").RobloxLocaleId);
playButton.Text = Locale.t("UI.Play");

This is a wrapper, not a replacement for LocalizationTable or Roblox automatic localization.

Audio​

defineAudio creates named native Sound instances under SoundService or a supplied parent. Every returned AudioHandle owns its Sound and supports play, pause, resume, stop, volume, linear tween fades, and cleanup.

const Audio = defineAudio({
	MenuMusic: { assetId: "rbxassetid://123", volume: 0.6, looped: true },
	Click: { assetId: "rbxassetid://456", volume: 0.8 },
});

const music = Audio.play("MenuMusic");
const nextMusic = Audio.crossfade(music, "MenuMusic", 0.5);
nextMusic.destroy();

Client-owned UI and music audio should normally be created on the client. Call destroy() on handles or the manager when their lifecycle ends.

Input​

InputManager maps game actions to ContextActionService; gameplay code receives action state rather than reading keys directly.

type Actions = "Interact" | "OpenMenu";
const Input = defineInput<Actions>();

Input.bind(
	"Interact",
	{
		keyboard: Enum.KeyCode.E,
		gamepad: Enum.KeyCode.ButtonX,
		mobile: true,
	},
	({ state }) => {
		if (state === Enum.UserInputState.Begin) print("interact");
	},
);

Input is client-only. Duplicate action bindings fail explicitly, and destroy() unbinds every action.

Prefabs​

Prefabs remain ordinary Roblox templates cloned with Instance.Clone(). PVInstance templates can receive a pivot, and attributes/configuration are applied before parenting.

const Prefabs = definePrefabs({
	Projectile: {
		template: projectileTemplate,
		pool: { initialSize: 8, maxRetained: 32 },
		reset: (projectile) => projectile.SetAttribute("Damage", 0),
	},
});

const projectile = Prefabs.spawn("Projectile", {
	parent: Workspace,
	pivot: spawnCFrame,
	attributes: { Damage: 10 },
});

Prefabs.release("Projectile", projectile);

Pooling is opt-in. A pooled prefab should provide reset for mutable state that is not reset by unparenting. Releasing an Instance to the wrong pool is rejected.

Entity registry​

The registry adds stable IDs and lookup to Roblox Instances without creating an ECS. IDs use the RoFrameEntityId attribute and default to HttpService.GenerateGUID(false).

const Entities = new EntityRegistry<{ kind: "npc" | "vehicle" }>();
const entity = Entities.register(model, { kind: "npc" });

print(entity.id);
print(Entities.getByInstance(model)?.metadata.kind);

Destroying an Instance unregisters it automatically. Destroying the registry disconnects its listeners but does not destroy registered Instances.

Object pool​

ObjectPool is generic and intentionally opt-in. Use it only after measuring a meaningful creation/destruction cost.

const parts = new ObjectPool({
	create: () => new Instance("Part"),
	reset: (part) => { part.Parent = undefined; },
	destroy: (part) => part.Destroy(),
	maxRetained: 64,
});

const part = parts.acquire();
parts.release(part);

Double release, foreign resources, and factories returning an already active object are rejected.

Environments and feature flags​

Environment configuration and feature flags are local and deterministic. They do not fetch remote configuration and must never be treated as client security controls.

const Environment = defineEnvironment({
	current: "development",
	development: { verboseLogs: true },
	staging: { verboseLogs: true },
	production: { verboseLogs: false },
});

const Features = defineFeatures({
	defaults: { NewInventory: false, NewHUD: true },
	environment: Environment.name,
	overrides: {
		development: { NewInventory: true },
	},
});

if (Features.isEnabled("NewInventory")) {
	// Enable the local integration.
}

Keep server and client configuration aligned through shared source, but enforce all permissions and authoritative state on the server.

Performance and ownership​

  • Repeated schedules chain native delayed tasks; they do not poll on Heartbeat.
  • State machines, registries, and feature flags use direct map lookups.
  • Assets are preloaded only when explicitly requested.
  • Audio, Input, Scheduler, EntityRegistry, pools, and prefab registries expose destroy() for lifecycle cleanup.
  • Pooling is never enabled globally or implicitly.
  • No Phase 10 platform services or gameplay modules are included.
