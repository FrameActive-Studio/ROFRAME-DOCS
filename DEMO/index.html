Coin Hunt demo

Coin Hunt is a small integration demo for the existing RoFrame framework. Eight gold coins sit on a 64-stud arena. Walk into a coin to collect it; it disappears for four seconds. The server owns rewards and profiles. Collector I unlocks after ten pickups, regardless of whether the double-coins feature is enabled.

Launch​

npm ci
npm run check
npm run build:place

Open build/ROFRAME.rbxlx in Studio, or run npm run watch and npm run serve in separate terminals and connect the Rojo plugin. Press Play, or start a local server with two clients. The current default.project.json launches Coin Hunt. Set demoConfig.enabled to false to return to the original Phase 8 UI example; the two examples are never discovered together.

The HUD shows a loading message until the server confirms PlayerReady and the client loads its authoritative Store snapshot. Its cartoon/simulator skin uses bold outlines, rounded shaded buttons, native shape icons and Fredoka One text. Coins, total pickups and Collector I progress appear in left-side counters; the bottom progress bar tracks actual pickups, not a separate XP or level system. The round status stays visible above the world.

When the replicated coin balance increases, the number makes a small 10% pop, briefly turns gold and settles in about 0.32 seconds. One small +N rises 16 pixels and fades over 0.6 seconds. Further gains within that interval aggregate in the same popup and restart the bounded pulse, rather than stacking effects. Initial snapshots, unchanged balances and spending never trigger the animation. The displayed balance updates immediately from the Store, without optimistic rewards or per-frame React renders. Native TweenService handles interpolation; RoFrame Cleanup cancels/destroys replaced or unmounted tweens and connections.

The main menu opens after loading. Play closes it. Press M, D-pad Up, or Menu [M] to open it again. M and the HUD button toggle it; D-pad Up passes through for native GUI navigation while a window is open. B closes the top window through CartoonModal's back-input policy; Escape follows the same policy when Roblox dispatches it to the game. Input passes through while typing. The sidebar opens Collection, Settings, Admin and Help directly. The counters' plus buttons open Collection; they do not purchase or grant currency.

Collection borrows the card-grid/detail-pane layout of an inventory, but displays only real demo milestones at 1, 5, 10 and 25 lifetime pickups. It adds no pets, items, equip/merge actions or rewards. Only Collector I is a persisted achievement and waits for the server's collectorUnlocked flag; other cards are a progress journal. Selecting a card updates the detail pane.

Settings can mute future pickup/achievement SFX and disable pickup popups. Achievement and command/error notifications remain visible. Settings are local to the session, not saved. Empty audio asset placeholders still remain silent. The menu does not pause gameplay; the Admin window's server pause action retains the existing server permission checks. Close any window with its X or backdrop.

Common presentation now comes from the optional @frameactive-studio/cartoon-ui public API. DemoController mounts CartoonThemeProvider and CartoonToastProvider through the existing UIController. Core UIRouter, useStore, NotificationCenter and RoFrame Input/Audio still own their existing responsibilities. The provider also themes neutral Core TextInput. Demo-specific layouts, milestone selection, switches and coin-gain effects remain in demo/client/ui; its duplicated cartoon.tsx is removed. Viewport events fit modals safely, including title/shadow overhang; narrow HUDs retain the logo/menu relocation. There is no polling, new asset dependency, extra queue or additional Remote.

demo/client/bootstrap.ts registers the inert Cartoon UI manifest before startup. demoConfig.cartoonUIEnabled controls both activation and the Controller mount; setting it false runs Coin Hunt without its HUD. It does not change the module's default-off behavior in other games. demoConfig.enabled=false still returns to the independent Phase 8 example. The demo server imports no Cartoon UI code.

The counter's valueContent slot hosts the existing gain-only effect; a balance decrease still does not celebrate. Toasts borrow the same three-entry Core center with three-second defaults/five-second achievement messages and whole-surface dismissal. Interactive windows now pop upward with a small overshoot, close with a faster downward shrink, and replay the pop when switching pages. Buttons lift on hover, squash on press and spring back around their centers with stable hit targets. Collection detail panels pop on selection; Settings knobs, progress, counters and toast entrances also animate. The last page remains mounted during exit and cannot trigger actions. The startup/error notice remains static. Modal X targets are now 44 px; standard counter/toast insets and TextInput styling follow the shared tokens. Their final alignment and native focus still need Studio review. Windows select a control automatically only with controller preferred input. Closing the final demo window clears GUI selection instead of returning to a HUD button, so movement input returns to the character. Switching from controller to keyboard also releases selection inside an open window; this does not change the native handling of text fields.

Gameplay is isolated under demo/src/demo. Core remains in packages/core/src/core. The regular client/server entrypoints select the discovery root. Demo server modules map exclusively to ServerScriptService.Demo; client modules map to StarterPlayerScripts.Demo. Only shared definitions and non-sensitive config map to ReplicatedStorage.Demo. The reusable UIController is registered by its import, without discovering the old example Controller.

Collection has no client request: native server touch events identify the Player, and the server checks the ready profile, the current living Character, the touched Character, an active registered coin, distance <= 6 studs, and Running state. A synchronous slot claim prevents two touches from awarding the same spawn. Respawn reuses that Part; no per-frame animation, loop, pool or new Remote is needed. Distance validation is not a full movement anti-cheat.

The round follows Loading → Ready → Running; an authorized panel action can switch Running ↔ Paused. Paused rounds award nothing. Existing respawn timers may still reveal coins during a pause, but collection stays disabled.

Profile and readiness​

RoFrameCoinHunt is player-scoped and persistent, version 1. Defaults are coins=0, totalCollected=0, joins=0, collectorUnlocked=false. Actions are the only demo mutation path; persisted counters have bounded integer validation. Future versions add sequential migrations in profile-options.ts.

joins increments on ProfileLoaded and is never replicated. Coins, total pickups and achievement status replicate only to the owner. A client's local state factory has joins=0, which is a default, not the server's private value. Admin setcoins changes spendable coins only, not lifetime pickups or achievements.

PlayerLifecycle loads the profile before PlayerReady. Load failures retain the existing Core logging/retry/kick path. Current Character references and the Died connection are replaced on each CharacterReady and released on removal/reset.

The client registers notification and readiness listeners before sending HUDReady(). The server replies with SessionReady() either immediately if the Player is ready, or from PlayerReady if the client arrived first. It sends no currency values; the client then loads the Stores. A one-shot 30-second timeout shows a retry message without polling; a later successful handshake can recover.

Networking, commands and permissions​

The demo adds one RoFrame network (one RemoteEvent and one RemoteFunction). Store replication continues to use the existing separate shared Store network.

Every client boundary validates even though the UI is typed and checks values locally. Currency and rewards never arrive as a client Store patch.

Open Admin in the sidebar, enter an exact username and amount, then press Run /setcoins. This invokes the RoFrame SetCoins command through typed Networking; /setcoins is the familiar panel label, not a chat slash-command parser. Pause/resume uses the same Command registry. Both successes and denials are audited server-side.

demo/server/server-config.ts keeps permissions server-only. The place's user owner and explicitly configured adminUserIds receive demo.admin. In Studio, the configured test ID -1 (normally Player1) also receives it; Player2 does not. Solo Play uses your real user ID, so add it to the server allowlist if the place has no user owner. Check the actual local test IDs if Studio assigns other IDs.

Development adapters and configuration​

The default backend is mock, including outside Studio, so launching this validation demo cannot accidentally write real user data. Mock records survive release/reload in the same running server and reset when that server ends. Stopping Play and restarting is not a durable persistence test.

To test persistence across separate servers/restarts, intentionally change demoServerConfig.persistence to "datastore", publish a dedicated test place, and enable Studio API access when testing that backend in Studio. The demo uses the separate RoFrameCoinHuntDemo DataStore and demo: key prefix through Core; there is no direct DataStoreService use in demo code. Core owns autosave, PlayerRemoving release and BindToClose. No demo shutdown callback competes with it.

demoConfig.doubleCoins sets the server's DemoDoubleCoins feature flag: false awards 1, true awards 2. Editing the client's flag cannot change server rewards.

Without a supplied collectorBadgeId, a demo-only injected BadgePlatform uses a synthetic positive ID inside the real RoFrame BadgeManager. It never calls BadgeService with that ID. The profile persists the one-time achievement flag. Supply a badge owned by the test experience to use the native wrapper instead. Failed awards are logged and may retry on a later pickup/rejoin; concurrent pickups share one pending award per Player.

Analytics emits demo_session_ready, demo_coin_collected, and demo_achievement_unlocked through the existing wrapper. The default injected adapter logs locally. Set nativeAnalytics=true only when testing native analytics in a suitable published experience.

Sound IDs are centralized in demo-config.ts / demo/shared/assets.ts. The supplied empty values are explicit silent placeholders. Configure audio assets permitted for your experience to hear pickup/achievement audio through RoFrame Audio. Finished Sounds are destroyed; an eight-second deadline also cleans failed loads. No invalid placeholder ID is requested. The Coin model is a server-local native Part template registered as Models.Coin and spawned via RoFrame Prefabs.

All visible text uses Localization keys, including the five required demo keys. English fallbacks work without a published LocalizationTable; native translator/table integration is left to the test experience's configuration.

Cross-server Messaging/MemoryStore usage is omitted: the local demo has no shared milestone that warrants external requests or quotas. Camera, gameplay modules, pooling and movement anti-cheat are also outside this small demo.

Logging, diagnostics and cleanup​

Core has no public general Logger. The demo's small structured sink connects Networking, Persistence, Platform and Command audit hooks, and logs lifecycle, collections and achievement events. See DEMO_CORE_ISSUES.md for the verified Core API gap and the Player Instance scope fix. No Core logger was added.

DeveloperTools activate only in Studio. Snapshots are server/client-local and do not expose private Store state by default. No diagnostics are sent to clients.

Cleanup owns component touch listeners, Character Died connections, lifecycle signals, network registrations, notification timers, input bindings, the React mount, Router, audio, round and coin respawn tasks. No demo polling exists.

Automated validation and limitations​

npm run check runs lint, strict source/test typecheck, roblox-ts compilation, all Node tests and the Rojo sourcemap. npm run build:place produces the place. npm ci, npm ls --depth=0 and git diff --check are also validation requirements.

tests/demo.test.ts uses the exact demo Store options and Command registrations with the real RoFrame registry/persistence/replication policies and mock ports. It checks actions/bounds, mock save/release/reload, owner-only replication, private fields, corrupt data rejection, rewards/features, achievement threshold, server collection gates, state flow and admin denials before mutation. demo-types.test.ts verifies compile-time names, directions and payloads. The Store regression test distinguishes Instance Players from table adapters. demo-ui-activation.test.ts covers module registration/configuration before startup, disabled UI gating and the actual M/Up input handler using injected ports. Module tests cover the shared progress/safe-fitting logic and all demo window dimensions; demo-specific tests retain HUD scale, milestone flags and gain rules.

Node integration tests do not prove native physics touches, React rendering, Studio multiplayer, gamepad/mobile input, badge delivery or native DataStore behavior. These require the manual tests below. No Studio multiplayer execution is claimed by this document.

Additional UI smoke checks: navigate through all four menu pages, select every Collection card, toggle both Settings switches, and resize/emulate portrait and landscape devices. Check that windows fit, large counters remain legible, and the menu does not hide Roblox's top bar. Verify mouse, touch and gamepad activation in Studio; automated layout tests do not prove native rendering or input behavior. Inspect the .28-second Back Out entrances, .16-second exits and backdrop fade. Close and reopen rapidly, switch pages while animating, select each milestone and toggle Settings repeatedly. There should be one window/focus owner, the latest controlled target, full borders/shadows and no action firing during exit. Check that hovering/pressing near a button edge does not cancel the click as it scales. Compare the module version against the source audit in CARTOON_UI_AUDIT.md: check counter labels/plus actions, selected tile borders, switch knobs, window body clipping, the X and toast positions. Navigate Up inside an open window, close with B, and check that GUI selection clears and character movement resumes. Repeat opening/closing with M, Play, X and backdrop on keyboard: WASD must move the character rather than select HUD buttons. With a dialog open, switch from controller to keyboard and back; check both selection release and reacquisition. Type in Admin before M/B/Escape; text input must keep its native handling. Inspect loading/error states without a dimmer or X. Start once with cartoonUIEnabled=false: no HUD, modal input action or toast viewport should appear; restore it before the normal multiplayer tests. For the coin feedback, collect one coin, enable doubleCoins in a separate run, then collect several coins quickly. Expect accurate +1/+2 or aggregated gains, only one popup and a return to the normal white number/scale. Loading a saved balance or reducing coins through Admin must not celebrate a gain.
