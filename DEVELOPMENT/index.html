Development workflow

Boundaries​

  • packages/cli/src is Node.js tooling with its own TypeScript configuration; Roblox runtime packages and the demo do not import it. See CLI.
  • demo/src/client may use client and shared code, but must not contain authoritative state.
  • demo/src/server owns authoritative behavior and may use server and shared code.
  • demo/src/shared must be safe to load in both runtimes.
  • packages/core/src/core contains the runtime-neutral kernel and its Roblox discovery adapter.
  • packages/core/src/core/network*.ts contains the shared Networking API, security pipeline, and native Remote adapter.
  • packages/core/src/core/store*.ts contains the Store runtime, scope registry, and server-authoritative replication adapter.
  • packages/core/src/core/persistence*.ts contains runtime-neutral persistence logic plus native DataStore and mock adapters.
  • packages/core/src/core also contains the independent Phase 9 utilities and their thin Roblox-native adapters.
  • Phase 10 platform services under packages/core/src/core are server-authoritative wrappers around Roblox services; their pure policies use injected adapters in tests.
  • Phase 12 DeveloperTools are opt-in, Studio-gated, bounded, and snapshot-based. Production runtime paths receive no observers unless explicitly enabled.
  • demo/src/server/services is the automatic discovery root for server Services.
  • demo/src/client/controllers is the automatic discovery root for client Controllers.
  • demo/src/server/components and demo/src/client/components are the runtime-specific Component discovery roots.
  • packages/<module>/src owns each optional gameplay module's manifest and server/client/shared/UI implementation. Phase 11 adds the module infrastructure but intentionally adds no gameplay module.
  • out and include directories are compiler output and must never be edited manually.

The runtime bootstraps are demo/src/client/index.client.ts and demo/src/server/index.server.ts. roblox-ts 3 requires index for folder entrypoints.

Coin Hunt is enabled by default and selects its discovery roots under demo/src/demo. Its server/client/shared output is mapped separately by Rojo. Set demo/src/demo/config/demo-config.ts's enabled to false to run the original example. See DEMO.md for the complete launch and validation instructions.

First setup​

rokit install
npm ci
rojo plugin install

For day-to-day development, keep npm run watch and npm run serve running in separate terminals, then connect the Rojo plugin in Roblox Studio.

Documentation website​

The Docusaurus configuration lives in website/ and reads the existing Markdown files directly from docs/. The sidebar in website/sidebars.js follows the groups, labels and order in docs/index.md, which is also the home page. Add new documents to both the sidebar and the overview. Use relative Markdown links (for example, [Kernel](KERNEL.md)) so links work both in the repository and on the website. .md files use standard Markdown; use .mdx for embedded React.

Run npm run docs:start while editing. For a production preview, run npm run docs:build followed by npm run docs:serve. The build fails on broken internal links, and CI builds the documentation alongside framework validation. For deployment, set DOCS_URL to the public origin and DOCS_BASE_URL to the hosting path (default /, with leading and trailing slashes).

The documentation's web theme mirrors the Cartoon UI package's ink, slate, blue and gold palette, rounded panels, thick borders and offset shadows. Styling lives in website/src/css/custom.css; compare it with packages/cartoon-ui/src/shared/theme/cartoon-theme.ts when updating the look. Fredoka One headings and Nunito Sans body text are self-hosted through Fontsource. The site opens in dark mode and also supports a matching light theme.

Publishing documentation​

The Publish documentation workflow in .github/workflows/docs.yml runs on documentation, website, package or build-configuration changes pushed to main. It also supports a manual run from GitHub Actions on main.

The workflow builds package declarations, validates and builds the documentation, then syncs only website/build/ to the main branch of the public FrameActive-Studio/ROFRAME-DOCS repository. Git history is retained, and unchanged builds do not create commits. The destination is generated output; make content changes in the framework repository instead of editing the published files.

The build uses DOCS_URL=https://frameactive-studio.github.io and DOCS_BASE_URL=/ROFRAME-DOCS/. The published documentation, including its API tab, is available at https://frameactive-studio.github.io/ROFRAME-DOCS/. GitHub Pages in the destination repository publishes from main / (root); .nojekyll preserves the prebuilt Docusaurus assets.

The framework repository's DOCS_PUSH_TOKEN Actions secret contains a fine-grained personal access token restricted to ROFRAME-DOCS, with Contents: read and write and the required Metadata: read-only permission. The built-in GITHUB_TOKEN only reads the source repository. Deploy keys are disabled for the destination. To rotate access before the token expires, create a replacement with the same repository and permissions, update DOCS_PUSH_TOKEN in ROFRAME, verify a deployment, then revoke the previous token. Never commit tokens or paste them into workflow files.

API documentation​

Open the API tab in the top navigation to browse the generated reference with its own sidebar. The Documentation tab contains the guides and their navigation.

TypeDoc generates the API reference automatically when npm run docs:start or npm run docs:build runs. After TypeScript changes, restart the documentation server or build again to regenerate the reference. The development server polls files once per second to keep reloads stable with the generated API directory on macOS. The public package entry points are packages/core/src/index.ts, packages/core/src/ui/index.ts and packages/cartoon-ui/src/index.ts. Export new public APIs through the relevant entry point to include them. Private, protected and @internal members are hidden.

Function signatures, generics, parameters and return types come from TypeScript. Descriptions, usage examples and behavior notes come from documentation comments:

/**
 * Registers a listener called whenever the signal fires.
 * @param callback - Receives the arguments passed to fire().
 * @returns A connection that can be disconnected or owned by Cleanup.
 * @example
 * ```ts
 * const connection = changed.connect((value) => print(value));
 * connection.disconnect();
 * ```
 */

See Signal.connect in packages/core/src/core/signal.ts for a complete example. Add @internal to exclude an exported implementation detail. TypeDoc does not infer behavioral descriptions from function bodies; undocumented exports still show their signatures and types. Generated Markdown in docs/api/ is overwritten on regeneration, so edit the source comments instead. This reference documents the Roblox/roblox-ts library API; it does not expose HTTP endpoints.

Generated output​

The Node CLI compiles to packages/cli/dist/, which is ignored by Git and packed for standalone installation. It does not produce Luau or use Rojo.

roblox-ts owns each package’s out/, plus demo/out/ and demo/include/. Rojo reads generated output through demo/default.project.json (forwarded by the root project). Place builds and sourcemaps are written to build/; Node test output is written to test-out/. All generated directories are ignored by Git.

Docusaurus writes static output to website/build/ and its cache to website/.docusaurus/; both are ignored by Git.

TypeDoc writes generated API pages and sidebar data to docs/api/, also ignored by Git.

If Studio cannot connect, verify that npm run build succeeds first, then confirm that no other process is using Rojo's default port 34872.
