Phase 10 Platform Services

Phase 10 provides server-authoritative wrappers for permissions, admin commands, badges, analytics, MessagingService, and MemoryStoreService. The wrappers add typing, validation, lifecycle ownership, and structured diagnostics while leaving Roblox as the underlying platform.

All public values and types are exported from packages/core/src/index.ts.

Security boundary​

  • Commands, badges, analytics, MessagingService, and MemoryStoreService are server-only.
  • Permission decisions that protect game state must be evaluated on the server.
  • Command arguments are validated at runtime even when the caller is TypeScript.
  • Cross-server messages and MemoryStore values are untrusted and validated when read.
  • These APIs do not expose admin remotes. A game that adds one must still use the Phase 4 networking validation and rate-limit pipeline.

Permissions​

Permissions map typed roles to typed permission names. Role resolution is cached per Player by default and can be invalidated when an external role changes.

type Role = "player" | "moderator" | "developer";
type Permission = "command.kick" | "command.teleport" | "internal.tools";

const Permissions = definePermissions<Role, Permission>({
	roles: {
		player: [],
		moderator: ["command.kick", "command.teleport"],
		developer: ["internal.tools"],
	},
	superRoles: ["developer"],
	resolveRoles: async (player) => {
		// Resolve Roblox group ranks, configured user IDs, or another server-owned source.
		return player.UserId === game.CreatorId ? ["developer"] : ["player"];
	},
});

if (await Permissions.has(player, "internal.tools")) {
	// Authorized server behavior.
}

Permissions.invalidate(player);

Unknown roles returned by the resolver fail explicitly. destroy() clears cached role resolutions.

Commands and admin actions​

The command registry is transport-independent. Chat or Networking adapters pass untrusted input to executeUnknown; direct server code may use the fully typed execute method.

interface AdminCommands {
	Kick(targetName: string, reason: string): void;
	SetLevel(targetName: string, level: number): number;
}

const Commands = defineCommands<AdminCommands, Permission>({
	permissions: Permissions,
	audit: (entry) => print(entry.command, entry.status, entry.actor.UserId),
});

Commands.register("Kick", {
	permission: "command.kick",
	validate: validators.tuple(
		validators.stringLength(1, 20),
		validators.stringLength(1, 120),
	),
	handler: ({ actor }, targetName, reason) => {
		// Resolve the target and perform the authoritative action on the server.
		print(actor.Name, targetName, reason);
	},
});

await Commands.execute(player, "Kick", "Target", "Rule violation");
await Commands.executeUnknown(player, commandName, untrustedArguments);

Each command supports an individual enabled flag. The registry also supports a global enable switch. Every success, denial, validation failure, disabled call, unknown name, and handler failure can be sent to the audit hook. A broken audit hook cannot break command execution.

The registry does not parse chat text and does not create a RemoteEvent. That integration belongs to the game and must remain server validated.

Badges​

Badge names are inferred from a central ID map. The manager delegates to BadgeService, caches positive ownership checks per server session, and emits a local Signal after a new award.

const Badges = defineBadges({
	Welcome: 123456,
	CompletedTutorial: 234567,
});

Badges.awarded.connect((player, badge) => {
	print(player.Name, badge);
});

if (!(await Badges.has(player, "Welcome"))) {
	await Badges.award(player, "Welcome");
}

Call clearPlayer(player) during removal if long-running test servers reuse fake Player objects. destroy() clears the cache and Signal listeners. Badge failures are structured and can be logged through BadgeOptions.logger.

Internal achievement progress remains game or Store state; RoFrame does not replace Roblox badges with a second achievement engine.

Analytics​

Analytics is a failure-isolated wrapper around native Roblox analytics methods. Logging returns false instead of interrupting gameplay when disabled, called from the wrong runtime, given invalid basic numeric input, or rejected by Roblox.

interface CustomEvents {
	SessionReady: {
		value: number;
		fields?: { environment: string };
	};
}

const AnalyticsEvents = defineAnalytics<CustomEvents>({
	enabled: Environment.name === "production",
	logger: (entry) => warn(entry.message),
});

AnalyticsEvents.custom(player, "SessionReady", {
	value: 1,
	fields: { environment: Environment.name },
});

AnalyticsEvents.funnel(player, {
	funnel: "Tutorial",
	step: 1,
	stepName: "Entered",
});

Supported native shapes are custom, economy, funnel, and progression events. Keep cardinality and custom fields within Roblox limits.

Cross-server messaging​

Messaging topics are typed and require one runtime validator per topic. A namespace is prepended to every native MessagingService topic.

interface ServerTopics {
	Announcement: string;
	CacheInvalidated: string;
}

const Messaging = defineCrossServerMessaging<ServerTopics>({
	namespace: "MyGame",
	topics: {
		Announcement: validators.stringLength(1, 200),
		CacheInvalidated: validators.string,
	},
});

const subscription = await Messaging.subscribe("Announcement", (message, sentAt) => {
	print(message, sentAt);
});

await Messaging.publish("Announcement", "Server restart in five minutes");
subscription.disconnect();

Malformed inbound data is ignored and reported. Subscriber failures are isolated. destroy() disconnects every owned subscription. Roblox MessagingService quotas still apply; RoFrame does not retry or spam requests automatically.

MemoryStore​

The MemoryStore factory exposes validated HashMap, SortedMap, and Queue wrappers. Every value is checked after a read and before a write.

const Memory = createMemoryStore({ namespace: "MyGame" });

const ServerCounts = Memory.hashMap("ServerCounts", validators.number);
await ServerCounts.set(game.JobId, 24, 60);
const players = await ServerCounts.get(game.JobId);

const Scores = Memory.sortedMap("Scores", validators.number);
await Scores.set("player:123", 9000, 300, 9000);
const leaders = await Scores.range(Enum.SortDirection.Descending, 25);

const WorkQueue = Memory.queue("Work", validators.string, 30);
await WorkQueue.add("refresh-cache", 120, 1);
const batch = await WorkQueue.read(10);
// Process successfully, then acknowledge the receipt.
await WorkQueue.remove(batch.id);

Expiration is constrained to Roblox's 45-day maximum. Queue reads default to waitTimeout = 0, so RoFrame does not introduce polling or indefinite waits. Invalid stored values fail explicitly and are never cast into the typed API.

The wrappers intentionally do not implement matchmaking, distributed locks, or retry loops. Those policies depend on the game and Roblox request budgets.

Logging and cleanup​

Platform log entries contain service, operation, level, code, message, optional Player, and original cause. Logger failures are isolated.

Long-lived ownership:

  • PermissionService.destroy() clears role cache.
  • CommandRegistry.destroy() disables and clears registrations.
  • BadgeManager.destroy() clears ownership cache and Signal listeners.
  • CrossServerMessaging.destroy() disconnects subscriptions.
  • MemoryStore and Analytics create no permanent connections or loops.

Phase 11 modules and Phase 12 diagnostics remain separate layers; see MODULES.md and DEVELOPER_TOOLS.md.
