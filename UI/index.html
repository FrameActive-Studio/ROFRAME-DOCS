UI Foundation

Phase 8 adds a client-only React-Lua foundation. RoFrame uses the official @rbxts/react and @rbxts/react-roblox packages; it does not implement a custom renderer or React replacement.

Studio example​

The default place now launches Coin Hunt, documented in DEMO.md. To run the original Phase 8 example below, set demoConfig.enabled=false in demo/src/demo/config/demo-config.ts. Both examples reuse the same UIController.

The repository includes an automatically discovered example that exercises the complete UI path:

  • React root ownership through UIController
  • a custom ThemeProvider
  • reusable Panel, Label, Button, TextInput, and ProgressBar components
  • typed screen navigation through UIRouter
  • timed, dismissible Notifications
  • useStore reading a server-authoritative replicated Store
  • local React state

Build and connect normally:

npm run watch
npm run serve

Open Roblox Studio, connect the Rojo plugin, and press Play. A centered RoFrame · Phase 8 panel appears automatically. Verify the following:

  1. The server-ready Player count is visible.
  2. Editing the text field updates the greeting.
  3. React-State erhöhen advances the progress bar and creates a Notification.
  4. Router-Seite öffnen changes the page without creating another ScreenGui.
  5. The warning button creates a differently themed Notification.
  6. Zurück returns to the first page.
  7. Clicking a Notification dismisses it immediately; otherwise it closes after four seconds.

The demo is isolated in:

  • demo/src/client/controllers/ui-example-controller.tsx
  • demo/src/client/ui/example-app.tsx
  • demo/src/server/services/ui-example-service.ts
  • demo/packages/core/src/ui-example/example-store.ts

Remove those four example files when starting a game-specific interface. The reusable Phase 8 foundation remains under packages/core/src/ui and packages/core/src/ui/ui-controller.tsx.

React root ownership​

UIController is discovered like every other Controller and owns every React root. Inject it into another client Controller and destroy the returned mount with that Controller:

import React from "@rbxts/react";
import { Controller } from "@frameactive-studio/core";
import { Screen, ThemeProvider, defaultTheme } from "@frameactive-studio/core/ui";
import { UIController, type UIMount } from "@frameactive-studio/core/ui";

@Controller({ dependencies: () => [UIController] })
export class MenuController {
	private mount?: UIMount;

	public constructor(private readonly ui: UIController) {}

	public start(): void {
		this.mount = this.ui.mount(
			"Menu",
			<ThemeProvider theme={defaultTheme}>
				<Screen>{/* application */}</Screen>
			</ThemeProvider>,
		);
	}

	public destroy(): void {
		this.mount?.destroy();
	}
}

Duplicate root names are rejected. Runtime shutdown unmounts every remaining root and destroys its unparented React container.

Themes and components​

Games define visual identity; RoFrame supplies only typed theme tokens and neutral components:

import { defaultTheme, defineTheme } from "@frameactive-studio/core/ui";

export const gameTheme = defineTheme({
	...defaultTheme,
	colors: {
		...defaultTheme.colors,
		primary: Color3.fromRGB(255, 120, 80),
	},
});

Reusable components require a ThemeProvider. Current primitives are Screen, Panel, Label, Button, TextInput, and ProgressBar. They expose common layout props while leaving game-specific composition to the application.

Store hook​

Load a client Store before mounting the application, then pass its StoreView into React:

const profile = await profileStore.client.load();

function Coins(): React.Element {
	const coins = useStore(profile, (state) => state.coins);
	return <Label text={`Coins: ${tostring(coins)}`} />;
}

useStore subscribes only to the selected slice and disconnects automatically on unmount. Use a module-level selector when practical so React does not recreate the subscription on every render.

Router​

UIRouter<TScreen> is an optional typed stack router:

const router = new UIRouter<"menu" | "settings">("menu");

router.open("settings");
router.back();
router.close("settings");

useRouter(router) re-renders a component when the active screen changes. The router uses RoFrame Signals and no polling.

Notifications​

Create one NotificationCenter, provide it above the application, and render one NotificationViewport:

const notifications = new NotificationCenter();

notifications.notify("Saved", {
	level: "success",
	durationSeconds: 3,
});

The queue is bounded, uses native task.delay, and cancels pending timers during dismissal or cleanup. A duration of zero keeps an entry until explicitly dismissed.

Performance and boundaries​

  • React and the renderer are imported only by client/UI modules; @frameactive-studio/core remains safe for server imports.
  • Store subscriptions, Router changes, and Notifications are event-driven.
  • There are no Heartbeat loops or UI polling.
  • One React root may host many screens; the Router changes content rather than creating ScreenGuis repeatedly.
  • UI never owns authoritative gameplay state. Server state reaches UI through validated Networking and replicated Stores.

Phase 8 does not implement Phase 9 Scheduler, Input, Assets, Audio, Localization, Prefabs, pooling, feature flags, or environments.
