Quick Start

Create a standalone game with create-roframe, then sync it to Roblox Studio. This guide uses the current starter (0.1.2) and Core 0.2.x.

Requirements​

  • Node.js 20.19+ and npm 10+ (node --version, npm --version). The current CLI supports npm; pnpm and yarn workflows are not supported yet.
  • Rokit on your PATH. The generated rokit.toml pins Rojo 7.7.1; rokit install installs it below.
  • Roblox Studio and the Rojo 7 plugin. After installing Rojo, run rojo plugin install once, then restart Studio. See the official installation instructions.
  • GitHub Packages access to @frameactive-studio/core. The starter and CLI are public on npmjs.org, but runtime packages are private. Ask the package owner for access before continuing. Have a GitHub personal access token (classic) with read:packages and permission to read the package ready.

The starter declares roblox-ts 3.x and TypeScript 5.9.3 as local development dependencies. npm install installs them; no global TypeScript compiler is needed.

Create and install​

Run these commands from the parent directory where you want your game:

npx create-roframe@latest my-game
cd my-game
rokit install
npm login --scope=@frameactive-studio --auth-type=legacy --registry=https://npm.pkg.github.com
npm install
npm run build
npm run doctor

At the login prompts, enter your GitHub username and use the classic token as the password. npm stores the credentials in your user configuration. Keep tokens out of project files and source control. See GitHub's npm authentication guide. The generated .npmrc routes runtime packages to GitHub; the CLI dependency is pinned to its public npm tarball so it still installs from npmjs.org.

There are no interactive setup choices. The generator creates files only; it does not install dependencies, configure credentials or initialize Git. --dry-run previews the files, and --help lists the available flags. Open the generated my-game folder in your editor. Commit package-lock.json with your project; subsequent installs can use npm ci.

Project structure​

my-game/
  src/
    server/
      index.server.ts          Server entry point
      services/                Add your Services here
      components/              Add server Components here
    client/
      index.client.ts          Client entry point
      controllers/             Add your Controllers here
      components/              Add client Components here
    shared/
      index.ts                 Shared types, configuration and modules
  default.project.json         Rojo mappings for server/client/shared code
  rokit.toml                   Pinned Rojo version
  tsconfig.json                roblox-ts configuration
  package.json                 Dependencies and npm scripts
  .npmrc                       Runtime registry mapping

The services, controllers and components subfolders are conventions; create them when adding code. Only the entry points and src/shared/index.ts exist initially. Compilation writes Luau to out/ and the compiler runtime to include/. Rojo maps server code to ServerScriptService, client code to StarterPlayerScripts, and shared code to ReplicatedStorage.Shared. Keep server-only code out of src/shared.

The generated server entry point already starts RoFrame:

src/server/index.server.ts
import { RoFrame } from "@frameactive-studio/core";

void RoFrame.startServer(script).catch(warn);

The client entry point does the same for each player:

src/client/index.client.ts
import { RoFrame } from "@frameactive-studio/core";

void RoFrame.startClient(script).catch(warn);

RoFrame discovers decorated ModuleScripts in the services or controllers folder below each runtime root, plus its components folder. With these entry file names, roblox-ts/Rojo make those folders children of the entry script; keep the generated script argument. Shared modules are loaded by importing them from the code that needs them.

Only Core is installed initially. Optional modules are configured in these entry points: register their runtime-safe manifests with RoFrame.registerModule and call RoFrame.configureModules before startServer or startClient. Installing a package alone does not activate a module. The Modules guide covers registration, activation and Rojo mappings; roframe.config.json is for CLI settings, not runtime activation.

Your first Service and Controller​

Create the following two files, including their parent folders. Services run on the server; Controllers run on each client. The start() hook runs after all discovered systems have finished init().

src/server/services/hello-service.ts
import { Service } from "@frameactive-studio/core";

@Service()
export class HelloService {
    public start(): void {
        print("[Quick Start] Server ready");
    }
}
src/client/controllers/hello-controller.ts
import { Controller } from "@frameactive-studio/core";

@Controller()
export class HelloController {
    public start(): void {
        print("[Quick Start] Client ready");
    }
}

No manual imports into the entry points are needed for these conventional folders. For instance-bound behavior, add decorated Components under the appropriate components folder; see Components.

Start development and connect Studio​

In a terminal inside my-game, start the compiler and leave it running:

npm run watch

Wait for a successful compilation. In a second terminal, also inside my-game, start the Rojo server:

npm run serve
  1. Open a new Baseplate in Roblox Studio with the Rojo 7 plugin installed.
  2. Open the Rojo plugin, connect to localhost:34872 (or the address printed by serve), and accept the initial sync if prompted.
  3. Open Output in Studio and press Play to run a server and a client.
  4. Look for [Quick Start] Server ready and [Quick Start] Client ready in their respective server/client output. These confirm that Rojo, compilation, discovery and both RoFrame runtimes work.

Keep both terminals running while editing. watch recompiles; Rojo syncs the result. Stop and start the play session to rerun startup hooks after changes. Stop the terminal processes with Ctrl+C when finished.

For a one-off build, use npm run build. npm run typecheck checks TypeScript without emitting files, and npm run doctor checks the project and toolchain after a build. To produce a place without a live connection, run npm run build:place and open the generated my-game.rbxlx in Studio.

Troubleshooting​

SymptomWhat to check
Node/npm version errorCheck node --version and npm --version; use Node 20.19+ and npm 10+.
401, 403 or 404 while installing CoreRepeat the GitHub npm login command above. Check token expiry, read:packages, package access and organization SSO authorization if required. Keep the generated .npmrc; Core is not on npmjs.org.
rokit or rojo not foundInstall Rokit, reopen your terminal so PATH updates, then run rokit install inside my-game. The VS Code Rojo extension alone does not put the CLI on PATH.
Destination already existsUse a new project name or another parent directory. The generator never overwrites an existing destination.
Missing out/ or include/, doctor reports missing pathsRun npm install, then npm run build; fix compiler errors before running doctor or Rojo.
Studio cannot connectKeep npm run serve running in the game directory, use its printed address, and check that the plugin and CLI are both Rojo 7. Close another Rojo server if the port is occupied.
No Service/Controller messagesCheck exact lowercase folder names and decorators, wait for a successful build, sync Rojo and restart Play. Check both output contexts and any startup errors. Keep the generated entry points and Rojo mappings.

Continue with Kernel and dependency injection, Networking, Stores, Persistence, Module development, or Packaging and releases when you need those features.
